## Purpose / Big Picture

The agent serves a local HTTP API, the Device API, to programs on the robot. `/v0.3` was served from a pre-release spec (`v0.3.0-next`). openapi has released `device/v0.3.0`, which changes three things the agent serves:

1. The manual sync moves from `POST /v0.3/device/sync` to `POST /v0.3/sync` (operationId `sync`). Its response, `SyncResponse` (was `SyncDeviceResponse`), reports durations instead of timestamps: `last_synced_secs_ago` (nullable), `last_attempted_sync_secs_ago`, `in_cooldown`, and `cooldown_ends_in_secs` (rounded up, exactly 0 when not in cooldown).
2. `GET /v0.3/device` replaces `last_synced_at`, `last_connected_at` and `last_disconnected_at` with nullable `last_synced_secs_ago`, `last_connected_secs_ago` and `last_disconnected_secs_ago`. Each is null if the event hasn't happened since the agent last started.
3. Each calibration in `GET /v0.3/calibrations/latest` carries a required, nullable `invalidated_at`.

The release also adds `POST /calibrations/latest/invalidate` and its `InvalidateCalibrationRequest`. That route comes in a follow-up PR; this PR leaves the generated model unused. `/v0.2` and its vendored spec do not change.

After this change, `curl --unix-socket /run/miru/miru.sock -X POST http://localhost/v0.3/sync` returns a body like `{"code":"success","message":"successfully synced","last_synced_secs_ago":0,"last_attempted_sync_secs_ago":0,"in_cooldown":true,"cooldown_ends_in_secs":15}`, `POST /v0.3/device/sync` is 404, and `GET /v0.3/device` returns `"last_connected_secs_ago": null` until the agent's MQTT client first connects in this run.

## Decisions

### Names

| New name | Alternatives | Why this one |
|----------|--------------|--------------|
| `server::State::started_at` (`DateTime<Utc>`) | `start_time`, `agent_started_at` | The repo names instants `<event>_at` (`last_synced_at`, `reported_at`); the owning struct already says it is the agent's. No existing `started_at` in `daemon/src/`. |
| `server::v03::response::device(device, now, started_at)` | `From<&models::Device>` (no room for `now`), `to_device` | Matches the sibling free function `response::latest_calibrations`, named for what it returns. |
| `server::v03::response::sync(outcome, now, started_at)` | `sync_response`, `From<&SyncOutcome>` | Same as above; it builds the `sync` operation's body. |
| handler `server::v03::handlers::sync` (was `sync_device`) | keep `sync_device` | v0.3 handlers are named for their operationId, now `sync`. |
| route group `routes::agent` (was `agent_info`) | keep `agent_info`, a separate `sync` group | The groups follow the spec's tags; `/sync` is now tagged `Agent`, and it is not "info". |

### Precedent

No new non-generated files. `libs/device-api-v03/src/models/{sync_response,sync_result,invalidate_calibration_request}.rs` are generated by `api/regen.sh`. The duration conversions follow closed PR #362 (branch `feat/device-api-cooldown-durations`), which rounded the cooldown up and the elapsed time down, but take today's code: timestamps stay in the domain types and the conversion measures them against the agent's clock when it builds the response.

### Left out

- `POST /v0.3/calibrations/latest/invalidate`: the follow-up PR.
- Monotonic time (`clock::Clock`): the syncer and device store keep `DateTime<Utc>` timestamps, so the durations come from `Utc::now()` minus the stored time. Moving them to monotonic instants is a separate change to the syncer and device store.
- Changing `models::Device` or the device file: the stored timestamps stay, `/v0.2` keeps reporting them, and only `/v0.3` turns them into durations.
- A `SyncOutcome` field for the response time: the conversion takes `now` from the handler, as `create_calibration` passes `Utc::now()` to its service.

### Open questions

- How is "since the agent last started" decided? Default: `init` in `daemon/src/app/run.rs` records `started_at = Utc::now()` before it opens storage or spawns the syncer, passes it down to where `server::State` is built, and the v0.3 conversion returns null for a timestamp before it. This covers both sources the same way: the syncer's in-memory state starts at the Unix epoch, and the device file keeps the previous run's times (including the disconnect written at shutdown). A wall clock stepped backward after start can null a real event until the next restart; this matches the wall-clock timestamps the agent already stores.
- Does `last_synced_secs_ago` in `GET /v0.3/device` come from the device file or the syncer? Default: the device file, as today's `last_synced_at` does, so `GET /device` never waits behind a running sync. `POST /v0.3/sync` reads the syncer's state, as today.

## Decision Log

- Decision: `started_at` is taken at the top of `init` in `daemon/src/app/run.rs` and passed through `init_optional_services` and `init_local_api_servers` into `server::State`, not stored on `AppState`.
  Rationale: `AppState::init` is at exactly the 50-line `funclen` limit, and the two lines it would need push it over. Taking the time where `server::State` is built would also work today, since the servers start before the poller and MQTT worker, but it would silently depend on that order.
  Date/Author: 2026-11-17, implement (source).

- Decision: keep measuring the device and sync times against the wall clock (`Utc::now()` minus the stored `DateTime<Utc>`, null before `started_at`), rather than tracking this run's events in memory with monotonic time.
  Rationale: the user chose it after the AI design review's high finding on `daemon/src/app/run.rs` (review comment 4596021645). Known limitation: on a robot whose clock starts at 1970, or at a stale saved time, and is corrected by NTP later, `started_at` is early, so the device fields can report the previous run's sync, connection and disconnection as this run's; a clock stepped the other way can report early events as long ago, or null them until the next restart.
  Date/Author: 2026-11-17, user.

- Decision: keep passing `started_at` explicitly from `init` rather than taking it where `server::State` is built.
  Rationale: the user confirmed the entry above; it keeps "since the agent last started" independent of startup order.
  Date/Author: 2026-11-17, user.

- Decision: `secs_ago`, `secs_until` and `secs_ago_since_start` live in `daemon/src/server/response.rs` as `pub(crate)` functions, not private in `server/v03/response.rs`.
  Rationale: they build no wire type, and `ARCHITECTURE.md` puts such code in `server/`, shared by the versions. `server/response.rs` already holds the version-neutral `calibration_content`, and the `pub(crate)` helpers mirror `server/request.rs`'s `split_list`, which is tested through the version conversions that call it; these are tested through `server::v03::response::{device, sync}`.
  Date/Author: 2026-11-17, self-review.

## Context and Orientation

The daemon crate is `daemon/`. Each Device API version is a module, `daemon/src/server/v02/` and `daemon/src/server/v03/`, holding `routes.rs` (route table), `handlers.rs` (axum handlers), `response.rs` (domain to wire conversions), `enums.rs` (enum conversions) and `request.rs`, over one generated crate (`libs/device-api-v03`, imported as `device_api_v03::models as device_server`). Generated code is never hand-edited.

`daemon/src/services/device/sync.rs` returns `SyncOutcome { code: SyncCode, message, state: sync::syncer::State }`. The syncer's `State` (`daemon/src/sync/syncer.rs`) holds `last_attempted_sync_at`, `last_synced_at` and `cooldown_ends_at`, all `DateTime<Utc>`, in memory, starting at the Unix epoch each run. `models::Device` (`daemon/src/models/device.rs`) is persisted to the device file and holds `last_synced_at` (set by `workers/poller.rs` on each successful sync), `last_connected_at` and `last_disconnected_at` (set by `workers/mqtt.rs`, and the disconnect also by `disk::Storage::shutdown`). These persist across restarts.

`ReportMetadata::invalidated_at` (`daemon/src/calibrations/report.rs`) is `Option<DateTime<Utc>>`.

`server::State` (`daemon/src/server/state.rs`) is built in `daemon/src/app/run.rs` from `AppState` (`daemon/src/app/state.rs`).

## Plan of Work

Milestone 1, source.

In `daemon/src/app/run.rs`, `init` sets `started_at = Utc::now()` as its first statement and passes it through `init_optional_services` and `init_local_api_servers`, which sets it on `server::State`. In `daemon/src/server/state.rs`, add `pub started_at: DateTime<Utc>`.

In `daemon/src/server/v03/enums.rs`, map `SyncCode` to `device_server::SyncResult`.

In `daemon/src/server/v03/response.rs`, replace `From<&models::Device>` with `pub fn device(device, now, started_at)` and `From<&SyncOutcome>` with `pub fn sync(outcome, now, started_at)`. Private helpers: `secs_ago(at, now)` is whole seconds from `at` to `now`, rounded down and never below 0; `secs_ago_since_start(at, now, started_at)` is `None` when `at < started_at`, else `secs_ago`; `secs_until(at, now)` is whole seconds from `now` to `at`, rounded up and never below 0. `cooldown_ends_in_secs` is `secs_until(cooldown_ends_at, now)` and `in_cooldown` is `cooldown_ends_in_secs > 0`, so the two agree by construction. `From<&ReportMetadata> for Calibration` sets `invalidated_at` to the RFC 3339 string or null.

In `daemon/src/server/v03/handlers.rs`, `get_device` and `sync` (renamed from `sync_device`) call the new conversions with `Utc::now()` and `state.started_at`. In `daemon/src/server/v03/routes.rs`, rename `agent_info` to `agent`, add `POST /{api_version}/sync` to it, and remove `/device/sync`.

In `ARCHITECTURE.md`, say that `/v0.3` reports these times as durations and how null is decided, and that `GET /v0.3/calibrations/latest` includes `invalidated_at`.

Milestone 2, tests. Mirror the existing v0.3 tests: `daemon/tests/server/v03/response.rs` (device and sync conversions: null before `started_at`, rounding, `in_cooldown` agreeing with `cooldown_ends_in_secs`; calibration `invalidated_at` both ways), `daemon/tests/server/v03/enums.rs` (`SyncResult` mapping), `daemon/tests/server/v03/handlers.rs` (`POST /v0.3/sync` returns 200 and the new body shape; `POST /v0.3/device/sync` is 404; `GET /v0.3/device` shape), and every test fixture that builds `server::State` (`tests/server/v02/{handlers,sse,response}.rs`, `tests/server/v03/{handlers,sse}.rs`, `tests/server/tcp.rs`, `tests/server/routes.rs`) gains `started_at`.
