## Purpose / Big Picture

The Miru agent runs on fleet devices that update independently of the backend. The agent fetches `Device` and `Deployment` (and related) payloads from the backend over HTTP and deserializes them with `serde_json` (see `agent/src/http/response.rs:45`, `serde_json::from_str::<T>`). Several status/type enums in the OpenAPI-generated client crate `libs/backend-api` are **closed** enums (plain `#[derive(Deserialize)]` with `#[serde(rename = "...")]` on each variant and no catch-all). The moment the backend introduces a new status string (e.g. a new `DeploymentActivityStatus`), `serde` fails to deserialize the *entire* containing payload, so every not-yet-updated agent stops processing sync/poll responses. This is a fleet-wide forward-compatibility break.

After this change: when the backend sends an unrecognized enum string, the affected enum deserializes into a new catch-all variant instead of erroring, the whole `Device`/`Deployment` payload still deserializes successfully, the agent maps the unknown value to a safe default in its own domain model (with a log line), and known values continue to serialize, `Display`, and round-trip **byte-for-byte identically** to today. Observable outcome: a unit test feeds a `Deployment` JSON payload whose `activity_status` is `"some_future_status"` and the payload deserializes successfully (today it errors).

## Surprises & Discoveries

(Add entries as you go.)

- Observation: The agent does NOT consume the backend-api enums directly in business logic. It has its own domain enums (`DplStatus`, `DplActivity`, `DplErrStatus`, `DplTarget`, `DeviceStatus`) defined in `agent/src/models/deployment.rs` and `agent/src/models/device.rs`. Conversion from the backend-api enum to the domain enum is generated by the `impl_status_enum!` macro in `agent/src/models/status.rs`, via `impl From<&$backend_type> for $name` which does an **exhaustive `match`** over the backend variants (`$backend_value => $name::$variant`). Adding a variant to a backend enum will therefore cause a non-exhaustive-match compile error there. This is the single agent-crate site that must be updated.
  Evidence: `agent/src/models/status.rs:72-80`; `agent/src/models/deployment.rs:24-184`; `agent/src/models/device.rs:20-32`.

- Observation: The backend-api enums derive `Copy` and are embedded in `Copy`-deriving structs (`libs/backend-api/src/models/device.rs:62`, `deployment.rs:71`, `base_deployment.rs:63`). A string-carrying catch-all variant would break `Copy` and cascade compile errors. The catch-all must be a **unit variant**, which is exactly what `#[serde(other)]` requires.
  Evidence: `grep -n Copy libs/backend-api/src/models/{device,deployment,base_deployment}.rs`.

- Observation: Outbound values sent back to the backend (`UpdateDeploymentRequest.activity_status` / `.error_status` in `agent/src/sync/deployments.rs:372-379`, and query params built from `s.to_string()` in `agent/src/http/deployments.rs`) are always constructed from the agent's own domain enums via `From<&DplActivity> for backend_client::DeploymentActivityStatus` (the `impl From<&$name> for $backend_type` arm of the macro). The agent never serializes a backend-origin catch-all value back to the backend, so losing the original unknown string (the one downside of `#[serde(other)]`) has no round-trip impact.
  Evidence: `agent/src/sync/deployments.rs:372-379`; `agent/src/models/status.rs:62-70`.

## Decision Log

- Decision: Use a unit catch-all variant with `#[serde(other)]` (named `UnknownValue`) rather than a string-carrying variant or a custom `Deserialize`/`#[serde(untagged)]`.
  Rationale: The enums must remain `Copy` (they are embedded in `Copy` structs). `#[serde(other)]` works only with a unit variant and the existing derived `Deserialize`, requires no hand-written deserializer, and preserves the existing per-variant `#[serde(rename)]` behavior exactly. The only downside of `#[serde(other)]` — it discards the original unknown string — is irrelevant here because the agent never re-serializes backend-origin enum values back to the backend (all outbound values are built from the agent's own domain enums). A string-carrying `untagged` fallback would break `Copy`, force edits across many structs, and add complexity for zero functional benefit in this codebase.
  Date/Author: 2026-05-15 / plan author.

- Decision: Keep `#[derive(Serialize)]` on these enums and do NOT add `#[serde(rename)]` / serialization handling for the catch-all.
  Rationale: `#[serde(other)]` only affects deserialization. Known variants keep their exact existing serialized form. The catch-all is never serialized in practice (see Surprises). If `serde` is ever asked to serialize the catch-all, the default derived behavior serializes the variant name `"UnknownValue"`; that path is unreachable in this codebase and adding a custom serializer would be dead code. This is documented with an inline comment on each catch-all variant.
  Date/Author: 2026-05-15 / plan author.

- Decision: Map the backend catch-all to the agent domain enum's existing default (with a `warn!`/`error!` log) by adding a wildcard arm to the `From<&$backend_type> for $name` match in the `impl_status_enum!` macro, mirroring the already-existing forward-compatible behavior of the domain enums' own custom `Deserialize` (which already maps unknown wire strings to the default + log — `agent/src/models/status.rs:96-116`).
  Rationale: The domain enums already define "unknown ⇒ default + log" semantics for their own deserialization; reusing the same default keeps state-machine behavior consistent and avoids introducing a new `Unknown` domain variant that would ripple through every `match` on `DplStatus`/`DplActivity`/etc. in the agent. No agent state machine needs a distinct "Unknown" behavior beyond the existing default.
  Date/Author: 2026-05-15 / plan author.

## Context and Orientation

This is a Rust workspace rooted at `/home/user/agent`. Relevant crates:

- `libs/backend-api`: an OpenAPI-generated HTTP client for the Miru Backend API. Files under `libs/backend-api/src/models/*.rs` carry the header `Generated by: https://openapi-generator.tech`. 4. `libs/backend-api/src/models/deployment_error_status.rs` — `DeploymentErrorStatus` (3 variants).
5. `libs/backend-api/src/models/deployment_target_status.rs` — `DeploymentTargetStatus` (3 variants).
6. `libs/backend-api/src/models/instance_format.rs` — `InstanceFormat` (3 variants).
7. `libs/backend-api/src/models/git_repository_type.rs` — `GitRepositoryType` (3 variants).

The single agent-crate consumer that performs an exhaustive `match` on these backend enums: the macro `impl_status_enum!` in `agent/src/models/status.rs`. Its extended form (the one taking `backend_type:`) generates:

    impl From<&$backend_type> for $name {
        fn from(status: &$backend_type) -> $name {
            match status {
                $( $backend_value => $name::$variant, )+
            }
        }
    }

This `match` is exhaustive over today's backend variants; a new variant makes it non-exhaustive (E0004). The macro is invoked for `DplTarget`, `DplActivity`, `DplErrStatus`, `DplStatus` in `agent/src/models/deployment.rs` and (the base form, no `backend_type`, so unaffected) for `DeviceStatus` in `agent/src/models/device.rs`. The base form (used for `DeviceStatus`) does not generate a `From<&backend_type>` and so needs no macro change — but note `agent` does not even import `backend_client::DeviceStatus` for conversion; it constructs domain `DeviceStatus` directly. `InstanceFormat` and `GitRepositoryType` are used in backend-api structs the agent deserializes (`InstanceContent`, `GitCommit`) but the agent converts those via separate `From` impls — to be verified in step 3; if any do an exhaustive match they get the same wildcard-arm treatment.

Non-obvious term: `#[serde(other)]` — a serde attribute placed on exactly one fieldless (unit) enum variant of a derived `Deserialize` enum; any input string not matching another variant's name/rename deserializes into that variant. It only affects `Deserialize`, not `Serialize`, and discards the unrecognized string.

Validation tooling: `scripts/preflight.sh` runs lint + tests (workspace + tools) in parallel and prints `Preflight clean` on success or `Preflight FAILED (...)` and exits non-zero on any failure.

## Plan of Work

### 1. Add a forward-compatible catch-all to each of the 7 backend-api enums

For every file in the list above, make two minimal edits. Example for `libs/backend-api/src/models/deployment_activity_status.rs`:

- Inside the `enum DeploymentActivityStatus { ... }` block, after the last existing variant and before the closing brace, add:

      /// Catch-all for enum values added by the backend after this agent was
      /// built. `#[serde(other)]` makes unrecognized strings deserialize here
      /// instead of failing the entire payload (forward compatibility). This
      /// variant is never serialized in practice; the agent only sends values
      /// built from its own domain enums.
      #[serde(other)]
      UNKNOWN_VALUE,

- In the `impl std::fmt::Display`, add a final match arm before the closing brace of the `match`:

      Self::UNKNOWN_VALUE => write!(f, "unknown_value"),

Apply the same pattern to all 7 files, using each enum's existing variant naming convention for the new variant name so the file stays internally consistent:

- `device_status.rs` → `DeviceStatus`: add `#[serde(other)] DEVICE_STATUS_UNKNOWN_VALUE,` and Display arm `Self::DEVICE_STATUS_UNKNOWN_VALUE => write!(f, "unknown_value"),`.
- `deployment_status.rs` → `DeploymentStatus`: `DEPLOYMENT_STATUS_UNKNOWN_VALUE`.
- `deployment_activity_status.rs` → `DeploymentActivityStatus`: `DEPLOYMENT_ACTIVITY_STATUS_UNKNOWN_VALUE`.
- `deployment_error_status.rs` → `DeploymentErrorStatus`: `DEPLOYMENT_ERROR_STATUS_UNKNOWN_VALUE`.

- `instance_format.rs` → `InstanceFormat`: `INSTANCE_FORMAT_UNKNOWN_VALUE`.
- `git_repository_type.rs` → `GitRepositoryType`: `GIT_REPO_TYPE_UNKNOWN_VALUE`.

Do not change the existing variants, their `#[serde(rename)]`, the derives, the `Default` impl, or the existing `Display` arms. Keep `Copy`/`Clone` (the catch-all is a unit variant, so `Copy` still holds). Do not add `#[serde(rename)]` to the catch-all (it is `other`, never matched by name on input).

Choosing `unknown_value` as the `Display` string is deliberate: it is not a valid backend value, so it cannot collide with a known wire value, and it is human-readable in logs/query strings. It is never sent to the backend in practice (see Decision Log).

### 2. Make the agent-crate conversion macro tolerate the new backend catch-all

Edit `agent/src/models/status.rs`. In the **extended** macro arm only (the one with `backend_type: $backend_type:ty` and `$backend_value:path`), change the generated `From<&$backend_type> for $name` so its `match` is no longer exhaustive over backend variants: add a wildcard arm that maps any unrecognized backend value (including the new `*_UNKNOWN_VALUE`) to the domain default, with a log line consistent with the existing custom-`Deserialize` behavior in the same file.

Replace:

    impl From<&$backend_type> for $name {
        fn from(status: &$backend_type) -> $name {
            match status {
                $(
                    $backend_value => $name::$variant,
                )+
            }
        }
    }

with:

    impl From<&$backend_type> for $name {
        fn from(status: &$backend_type) -> $name {
            match status {
                $(
                    $backend_value => $name::$variant,
                )+
                other => {
                    let default = $name::$default;
                    $log_macro!(
                        "{} backend value {:?} is not recognized, defaulting to {:?}",
                        $label, other, default
                    );
                    default
                }
            }
        }
    }

Notes:
- `$log_macro`, `$label`, `$default` are already macro parameters in scope for this arm (used by the `@base` arm). The backend enums derive `Debug`, so `{:?}` on `other` compiles.
- Do **not** modify the `impl From<&$name> for $backend_type` arm: the domain enum has no catch-all, so that match stays exhaustive and outbound values remain exactly the known wire values. This preserves round-trip behavior for all known values.
- The `@base` arm and the simple (no-`backend_type`) arm are unchanged; `DeviceStatus` (simple form) needs no change.
